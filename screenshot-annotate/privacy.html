SnapRedact privacy policy

Publisher: Matheus da Silveira Mello
Contact: matheus.mello.developer@gmail.com
Effective date: 8 November 2026

SnapRedact 0.1.1 processes screenshots on your device. No account, servers, uploads, analytics, advertising or tracking are used. Nothing is transmitted to us.

This policy covers the Chrome and Firefox editions.

Consent and local processing

Before capture or scanning, choose Agree and continue in the popup. Not now leaves capture disabled. Settings shows live consent status. Withdraw consent blocks new captures, pending capture handoffs, and Copy/Download from existing editors. Agreeing again does not reauthorize an earlier capture.

Capture reads the current tab's pixels and page geometry: viewport dimensions, device pixel ratio, scroll dimensions and offsets, and element positions and styles needed to select a scrolling panel and hide repeated headers. Full-page capture scrolls temporarily, then restores scroll position and changed styles. Selection uses pointer or keyboard coordinates locally.

With Auto-blur enabled, the helper scans DOM text nodes (excluding SCRIPT, STYLE, NOSCRIPT and TEMPLATE parents) and input/textarea values (excluding password and hidden inputs) for email addresses, phone numbers and card-like numbers. Only matching rectangle positions reach the editor; extracted text is not sent or stored. This scan is not a guarantee: review redactions before sharing.

Session data and stored data

New capture frames, pixels, geometry, auto-blur rectangles and editing history stay only in session memory. The background context hands a capture once to its assigned editor tab. Closing or reloading the editor discards it; a background-context restart before handoff can also lose a pending capture. No new capture database, capture store or Cache entry is created. Only an explicit Copy, Download, or the explicitly selected quick-copy capture action exports pixels.

Only these new persistent records are kept: default export format and Auto-blur/quick-copy preferences in extension localStorage; and consent version, agreement timestamp and random consent epoch in the separate snapredact-consent IndexedDB database. Settings and consent are not encrypted by SnapRedact, are not synced and are not transmitted. The obsolete boolean preference database is removed.

Chrome edition only: On an update from 0.1.0, old captures are preserved until you choose deletion. The popup flags old captures and Settings reports “N captures saved by an earlier version are still stored in this browser”. Delete old captures asks for confirmation and then deletes the entire snapredact database. Cancel preserves it. This version never writes new captures there and does not read old image/title/time fields; it only counts records. This version can't open or export these captures. Delete them when you no longer need them. Old captures are not encrypted by SnapRedact. Removing the extension normally removes its local data, but does not erase downloaded files, clipboard data or browser/system backups.

Page titles, URLs, times and exports

Neither tab.title nor the captured page's document.title is read. The editor always has the generic title “SnapRedact editor”; its address contains a random capture identifier and optional quick-copy flag, never a source title, URL or capture time. SnapRedact does not call browser history APIs. Chrome and Firefox may independently retain extension-page visits, random identifiers and visit times in history/session records.

In Chrome and Firefox, the popup and background context read tab.url transiently only to check page eligibility. Both check allowed schemes (HTTP, HTTPS or file); Chrome also checks file-access eligibility, and Firefox also checks sites it restricts. The address is never stored, logged, put into messages or displayed. Runtime sender extension URLs are checked to authorize extension pages; these are not source-page addresses. Errors omit address strings. Page pixels and locally scanned text can themselves contain titles, URLs or times visible on the page.

There is no capture timestamp. The clock is used for capture throttling, consent agreement time, UI timers and export filenames. Download names are generic snapredact-YYYYMMDD-HHMMSS using local export time, with a format extension. PNG and JPG are fresh canvas encodings: no source EXIF, page title, URL or visit-time metadata is copied. The local PDF writer embeds fresh JPEG pixels and writes no Title, CreationDate, ModDate or other document information dictionary. The filename export time and any information visible in image pixels remain in exports. Copy places a PNG on the system clipboard; Download creates the file you request. Other apps or your operating system may retain these exports and file times.

Permissions and questions

activeTab authorizes capture after your toolbar action; scripting injects the bundled local helper after consent. No host permissions, persistent capture-storage permission, remote code or external fonts are requested. Chrome's own pages and the Chrome Web Store cannot be captured. Local files in Chrome require “Allow access to file URLs”. Firefox protects internal pages, addons.mozilla.org and other sites Firefox restricts, including dynamically quarantined domains. Firefox is desktop only; private windows are not supported. Firefox local-file access depends on browser and administrator policy; no Chrome-style file toggle is available. Firefox uses an event page; unloading that page can discard a pending capture. Firefox clipboard export requires clicking Copy or Copy & close. Manage Firefox shortcuts in about:addons. AMO's data_collection_permissions declaration is none because SnapRedact transmits no data off the device; local access and processing are described above.

We hold no server copy to retrieve or delete. Contact the publisher with questions. Policy changes will be published with an updated effective date.
