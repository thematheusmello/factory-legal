Sheetkeel privacy policy

Effective date: 8 November 2026

Updated 15 November 2026

Sheetkeel was previously called GridGrab.

This policy explains how the Sheetkeel – Table & List to CSV/Excel browser extension (“Sheetkeel”) handles information. Sheetkeel is published by Matheus Mello, an individual developer based in Portugal (“I”, “me”). Contact: matheus.mello.developer@gmail.com.

Scope and free use

This policy covers the Sheetkeel editions for Chrome and Firefox. Both are free, work locally and require no account; there is no Pro plan and no daily export cap. Neither edition uploads extracted data or makes extension-initiated network requests. There is no analytics, advertising, telemetry or remotely loaded executable code. Normal website activity and browser-managed services remain subject to their own policies.

Page access and processing

Opening Sheetkeel lets its bundled code detect tables and repeated lists in the selected tab. It reads page text and, for lists, link and image URL values; it does not fetch those URLs. Detection uses visibility checks, but text inside a selected cell can include descendant text. Preview and selected rows are held in popup memory, rather than saved as page content in extension storage.

Both editions request only activeTab, scripting and storage, with no standing website host permissions. These allow temporary access to the selected tab, execution of the bundled reader, and local storage of preferences, taught Next-page selectors and review-prompt state. Regular HTTP/HTTPS pages are supported; local file access depends on browser permission. Browser and store pages may block access.

Chrome and Firefox editions

The Chrome and Firefox editions share the same behaviour. Both can outline and scroll to a candidate on the page. These inline style changes can be observed by the page’s own scripts; extracted rows are not inserted into the page.

  • Popup-close cleanup: in both editions, when the popup connection closes, the content script removes the highlight, restores the previous outline styles and drops its candidate references.
  • Private windows: both manifests disable the extension in private / Incognito windows.
  • Storage: both editions store the same local keys, described under “Retention and control” below.
  • Firefox declaration: the desktop Firefox edition declares that it collects no data.

Limits, clipboard and downloads

Both editions allow unlimited TSV, CSV, XLSX, Markdown and JSON exports, with no daily export cap or row limit. CSV and XLSX are generated locally as downloads; TSV, Markdown and JSON are written to the clipboard only when you select the corresponding action. Neither edition reads your clipboard.

Download filenames include the source host name (or “page” when absent) and date. The browser may retain download history. Files and clipboard copies can contain sensitive source data and remain wherever you save or paste them; uninstalling Sheetkeel does not remove those copies.

Review untrusted page data before opening or pasting it into a spreadsheet. Spreadsheet applications may interpret some cell values as formulas; do not assume every installed edition neutralises those values.

Retention and control

Extension storage uses chrome.storage.local in the browser profile, with no extension-managed sync. In both editions it holds only:

  • CSV preferences: the delimiter and the UTF-8 BOM setting;
  • taught Next-page selectors, saved per site origin (a selector for the page’s Next control, not extracted rows);
  • review-prompt state: a count of successful exports in any format, including TSV, and a flag recording that you dismissed the prompt. After three successful exports a dismissible review link may appear; it never opens automatically. This count never limits exports and has no daily reset.

Extracted table and list rows are not saved in extension storage. A profile upgraded from version 0.1.1 may still contain that version’s daily-use data; the current version neither reads nor updates it. The welcome tab opens only on first install, and no install or welcome flag is stored.

Stored values remain until replaced, the extension’s local data is cleared or the extension is uninstalled. In Settings, “Forget saved Next buttons” removes the saved Next-page selectors; it does not clear the other keys. There is no general clear-all control in the extension. Popup memory ends when the popup closes, and in both editions page-side highlights and candidate references are removed when the popup connection closes. Uninstalling removes extension storage but not files you downloaded or clipboard copies.

Developer contact and your rights

I do not receive the data processed locally by the extension. If you email me, I receive the information you choose to send and use it to answer and handle your request, retaining it only as needed for that purpose or applicable legal obligations. Do not send extracted data unless it is needed for your request and you are entitled to share it. I do not sell personal data or share it for advertising.

For personal data I hold, you may request access, correction, deletion, restriction, objection or portability where applicable by contacting matheus.mello.developer@gmail.com. You may complain to the Portuguese data protection authority, the Comissão Nacional de Proteção de Dados (cnpd.pt), or your local authority.
